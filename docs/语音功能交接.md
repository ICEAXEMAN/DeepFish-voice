## 3. 代码是怎么接的

### 3.1 Voice.cs

- 启动时 `Voice.Load(Path.Combine(Places.Root, "voice"))`，读 `index.json`
- 键会去掉半角/全角空格再比对；文件不存在就整包当没有（不报错、不影响她说话）
- `Find(text)` 返回 wav 绝对路径或 null

### 3.2 四个发声点（PetWindow.cs）

统一走 `Speak(text)`：

```csharp
private double? Speak(string text)
{
    var file = voicePack?.Find(text);
    if (file == null) return null;
    try { return PlayVoice(file); }   // 返回录音长度（秒）
    catch { return null; }
}
```

调用点与停留时间处理：

| 位置 | 处理 |
| --- | --- |
| `PlayTextIdle`（固定嘀咕） | 先 Speak，再打字；`Delay(max(5s, 录音+0.4s))` |
| `SayTouch`（触碰反应） | 同上；`max(按字数估的, 录音+0.4s)` |
| `PlaySkit`（小剧场） | 每个 step 一句；有录音的 `max(0.9s, 录音+0.45s)`，无录音/纯动作用 `step.Seconds` |
| `PlayEvent`（事件） | 同小剧场；`max(line.Seconds, 录音+0.4s)` |

嘴型不用额外写：`PlayVoice` 会把 wav 转成逐帧音量（`Behavior.VoiceLevels`），`UpdateMouth` 按播放位置驱动。

**文件锁**：`MediaPlayer` 播完不关会一直占着 wav，换文件时拷不进去。现在 `PlayVoice` 打开前先 `Close()`，
播放结束（`UpdateMouth` 里 voice 置空）也 `Close()`。

### 3.3 音量

- `Settings.Volume`（0–1，默认 0.8，`Checked()` 里夹住）
- 启动：`voicePlayer.Volume = settings.Volume`
- `update_settings` 收到 `volume` 立即生效并 `Save()`
- `get_state` 输出 `volume`
- 番茄钟提示音：`chimePlayer.Volume = settings.Volume * 0.75`
- 只管她自己的声音，不动系统音量

### 3.4 语速

不是参数，是**音频文件本身**被 `ffmpeg -filter:a atempo=0.95` 放慢过。
以后新生成的台词也要慢，所以生成脚本里 `speed_factor` 已改成 **0.95**（`tools/_gen_voice.py`）。

### 3.5 托盘音量条

`MainWindow.xaml` 里「衣服和配饰」下面新加一张 **声音** 卡片：

```xml
<Slider x:Name="VolumeSlider" Minimum="0" Maximum="100" TickFrequency="5" IsSnapToTickEnabled="True"/>
```

代码：拖动 → `Queue("volume", 值/100)`（批量 `update_settings`）；`Apply()` 里 `Fresh("volume")` 时回填。
刻度：静音 / 50% / 100%。

### 3.6 events.txt

在原事件段落**末尾追加**了 41 行（2 句和原文重复的跳过了），另外新增三段：

```
# 新会话 0        2 条
# 中断 30         2 条
# 思考超时 120     1 条
```

⚠️ **同名 `# 事件名` 段落会互相覆盖**（`EventBook.Parse` 里 `found[name] = …`），
加台词必须插进**原有段落内部**，不能另起一段同名标题。

## 3.7 实时语音（GPT-SoVITS v5turbo）

**她现在字幕中文、声音日语**（2026-11-11 用户定的）：`say` 的 `text` 写中文当字幕，
另给一个 `speech` 写对应的日文当声音：

```json
{"text": "这个项目做完了，你看看", "speech": "このプロジェクト、終わったよ。見てみて"}
```

- 给了 `speech`：整段合成一个气泡，字幕显示 `text`，声音念 `speech`
- 没给 `speech`：有假名直接念日语；纯中文先翻成日语再念，字幕仍保持中文
- `text` 里不要用换行配 `speech`（一个气泡放不下多行），要分句就分次调用

没有 `speech` 时：有假名直接念日语；纯中文先翻成日语再念（2026-11-11 定）。

她**现编的话**没有预录，所以 `say` 的时候现场合成：

```
audio 参数    → 有就直接播
预设录音      → voice\index.json 里查得到就播（零延迟）
实时合成      → 都没有，就 POST 到本机 GPT-SoVITS（默认 http://127.0.0.1:9880），拿 wav 再播
```

- 中文翻译先走 Google；Google 返回 429/超时再退到 MyMemory（只发当前这一句，结果缓存）。
- **字幕中文、声音日语**（2026-11-11）：句子里有假名 → 直接按日语合成；参考跟着当前语音包走：
  两套的参考文件都叫 `语音参考.wav`：
  青春、活力用 `voice\ref\语音参考.wav`（prompt `わたくしへのご意見、ご要望などはこちらの意見欄にご記入ください。`），
  冷静、沉稳用 `voice_calm\ref\语音参考.wav`（prompt `自信がないと言いますか、なんかよくわからないです。`）。
  没有假名 → 先把这一句发到 Google 翻译（`translate.googleapis.com`，zh-CN → ja）翻成日语，再用同一个
  日语参考合成；翻译失败就只打字，绝不退回中文配音。翻译结果只在内存缓存，不落盘。
- 旧的 `hello.wav` / `zh_boot.wav` 等参考已经归档；`speech` 给日语时仍然优先按 `speech` 念。
- 切换语音包后，下一次实时语音就会用新包的参考；缓存 key 带了参考路径，所以两套不会串音。
- **语音总开关 `voice_enabled`**（2026-11-11）：关掉后 `Speak` / `PlayVoice` / `Tts.Speak` 全部静音，托盘把「实时语音」「语音服务开机自动启动」「音量」收起；固定语音包仍可见。
  关掉时还会把 `TtsEnabled`/`TtsAutostart` 一起置 false，并调用 `Tts.Stop` 停掉后台 GPT-SoVITS；打开时恢复两者、调用 `Tts.Warm` 启动并预热服务。
- 完整包默认 `TtsEnabled=false`、`TtsAutostart=false`：用户不手动打开「实时语音」就不会连接/调用 GPT-SoVITS。
- 多气泡的 `say` 一句一句合成：第一句先合成再说，后面的边听边合成（`later` 队列），不会一句一句干等
- 英文读法（2026-11-11 改）：文件名/扩展名（`.jpg`、`.wav`、`.png`、`photo.jpg`…）按字母逐个拼；
  完整的英文单词先查常用表（bug→バグ、token→トークン、GPT→ジーピーティー…），查不到的用
  Google `en→ja` 翻成日语再合成（type→タイプ），不再把 type 逐字读成「ティーワイピーイー」；
  单字母 / 全大写缩写仍按字母读。字幕仍是原文。
- 采样：`temperature 0.7`、`top_k 10`（默认 1.0 会偶发念糊，比如「終わったよ」被念成「おーたよー」）
- 语速：`settings.tts_speed`（默认 0.95，和预录音一致）
- 缓存：`%TEMP%\fishpet-tts\<哈希>.wav`，同一句话第二次直接播；哈希里带了参考音频、prompt、语速和参数版本
- 服务没开：连接失败就只打字，`errors.log` 只记一次，不打扰
- 冷启动第一次约 15 秒，所以窗口创建时会**偷偷合成一句「起動テスト」暖机**；之后稳定 1.5–3 秒一句
- 超过 60 字的单句不合成（等太久不如直接打字）
- 实测（temperature 0.7）：日语 3 句全对；中文整句「报告一个好消息，所有测试都过了」「这一版我把测试全跑了一遍」全对，
  只有极短的口语句（「第二句也能出声」）偶尔还会听岔

**怎么起服务**（不双击也行，命令行一样）：

```powershell
cd D:\GPT-SoVITS-main\GPT-SoVITS-v2pro-20261006
.\runtime\python.exe .\api_v2.py -a 127.0.0.1 -p 9880 -c .\tts_infer_turbo.yaml
```

或者双击插件根目录的 `启动语音服务.bat`（内容一样）。

**桌宠自己拉服务**（仅当用户把 `tts_enabled` 和 `tts_autostart` 都手动打开后）：服务没在跑时，桌宠才会启动它——
启动时（`Tts.Warm` → `Ensure`）和说话失败重试时（`Speak` 里）都会调 `Ensure`：
先探测 `/docs`，不通就按 `tts_dir`（空 = 自动找：先看桌宠上一级的 `语音服务\`，再看 D 盘那份）启动
`runtime\python.exe api_v2.py -a 127.0.0.1 -p 9880 -c tts_infer_turbo.yaml`，然后最多等 90 秒（说话时只等 20 秒，别卡住）。
托盘「声音」卡片里有开关「语音服务开机自动启动」（`tts_autostart`）。完整包默认 **关**；只有用户手动打开并同意后才生效，不会自行拉起。
**注意用 `python.exe` 不用 `pythonw.exe`**：pythonw 下 `sys.stdout` 是 None，api_v2.py 会起不来（2026-11-10 踩过）。

**关掉实时语音会停掉服务**（2026-11-10）：控制台把「实时语音」开关关掉（`tts_enabled=false`）时，
桌宠会把监听 `tts_url` 端口的 python 进程杀掉（只认端口 + 进程名 python，别的 python 不动），
省下约 1 GB 内存和 3–4 GB 显存；再打开时桌宠会先把它热起来（`Ensure` 异步跑，不等）。
日志：`实时语音关了，顺手停掉语音服务（PID xxx）`。
**服务是独立进程**（2026-11-10 改）：桌宠拉服务时走 `explorer.exe → 临时 vbs → python.exe`，
让它不在桌宠/DSH 的进程树里——DSH 退出不会把它带走，下次开 DSH 它已经是热的。
实测：杀掉桌宠，服务 PID 不变、`/docs` 仍然 200。
登录自启的 `DeepFishTTS.vbs` 也重写了：先探测 `/docs`，不在才启动，启动后最多盯 60 秒，还不行再试一次，
日志写在 `%TEMP%\fishpet-tts-start.log`。
**开机自启（旧的手动方案，默认不安装）**：只有用户自己决定时才可以放一个启动 vbs 到 Startup；完整包不会自动创建或调用它，默认 `tts_autostart=false`。

**托盘开关**：控制台「声音」卡片第一行「实时语音」。完整包默认 `tts_enabled=false`；只有用户本人手动打开并同意后才会调用 GPT-SoVITS。关掉就是只打字不出声；开关状态跟着 settings.json 走。

⚠️ **必须带 `-c tts_infer_turbo.yaml`**，用默认配置会加载 v5dev，不是 v5turbo。

开关：`update_settings {"tts_enabled": false}` 就退回纯打字；`tts_url` 能指到别的机器。

## 4. 数据格式

`voice/index.json`：

```json
{
  "收到，我看看": "G-01.wav",
  "♪～啦啦～♪": "H-46.wav"
}
```

- 键 = 台词原文（去空格后），值 = `voice\` 里的文件名
- 多气泡台词（原文用「｜」分隔）在安装时**按句拆开各登记一次**
- 带 `{等级}` 的 3 条没有录音（运行时才知道填哪个词）
- 音符那 4 条：GPT-SoVITS 拒收 `♪`，合成时念「ららら」，但**索引键仍是带 ♪ 的原文**

`语音包/语音索引.json`（给页面和安装脚本用）：

```json
[{"category":"preset","group":"A","idx":2,"name":"A-02.wav","path":"全部语音/A_待机嘀咕/A-02.wav",
  "jp":"…","cn":"…","mood":"得意·俏皮","score":1.0,"dur":8.29}, …]
```

## 3.8 专注陪伴时的语音规则（2026-11-09 加）

用户开「专注陪伴」（番茄钟 25 分钟，panel op=focus action=start）时：

| 会出声 | 不出声 |
| --- | --- |
| 摸她 / 戳她（SayTouch，没有专注判断） | 待机嘀咕（MutterFor、PlayTextIdle） |
| 工作事件：授权、等你、完成、长任务完成、子任务完成、出错、编译失败、测试通过、该休息、番茄开始/结束/休息结束 | 小剧场（PlaySkit 直接返回，连语音一起停） |
| | 整点报时、亲密度台词（ehavior.Quiet 挡着） |

实现：PetWindow.Bond.cs 里 FocusWork（Work 段为真）和 FocusEvents（白名单），
Event() 里的判断从「专注时只放优先事件」改成「专注时只放优先事件 + 白名单事件」。
休息段（Break）不受限，小剧场照常演（RestSkitLater 用 force 绕过）。

**跟着音乐跳（2026-11-10 改）**：收到音乐后不再自己算参数（旧 `Dance.Pose`），
直接按顺序演身体动作「摇摆一 / 摇摆二 / 慢摇」——一句话演完再接下一句（`body.Apply` 的返回值就是这一句的时长），
轻/慢（响度 < 0.32 或 BPM < 84）只演「慢摇」，其余摇摆一、摇摆二交替。
逻辑在 `src/FishPet/PetWindow.Dance.cs`；旧的 `Dance.cs` 保留着没人调用了。

**音乐软件白名单**（2026-11-10）：`audio\probe.ps1` 每秒枚举一次 WASAPI 音频会话，在 JSON 里多吐一个
`"apps":[["spotify",0.42],["chrome",0.11]]`（名字小写、只取最响的 4 个）；`Music.AppPlaying(白名单)` 判断
白名单里有没有哪个应用电平 ≥0.015，只有命中才跳。白名单在设置 `music_apps`（逗号分隔的进程名），默认：
`cloudmusic,qqmusic,qqmusicclient,spotify,applemusic,itunes,music,kugou,kuwo,qishui,musicbee,foobar2000,aimp`。

**律动的幅度和频率**（2026-11-10 用户反馈「太快、太大」之后）：
`PetWindow.Dance.cs` 里 `wanted = Dance.Seconds(word, BPM) * 2`（一句演两倍时长 → 摇摆频率减半），
`body.DanceToBeat(word, wanted, .5)`（size 0.5 → 幅度减半）；另外加了 1.5 秒的丢拍宽限，
拍子偶尔断一下不会「跳一下马上停」。

**小剧场不触发的排查（2026-11-10）**，按影响大小排：
1. 一直在「跟着音乐跳」——`Dancing` 会当成 busy 传给 `behavior.Tick`，所有待机动作（含小剧场）都不抽。
   当时白名单阈值 0.015 太低，网易云暂停时残留 0.016 就算在放歌，所以她整天在跳。阈值已提到 **0.05**。
2. 被挡住的那次会丢掉——`Behavior` 先推进 `nextIdle` 再回调，`PlaySkit` 因为 `MutterBlocked`（刚说完话的 10 秒、正在说）直接 return。
   现在改成 `behavior.SkitMissed()` → **45 秒后重试**。
3. 三类待机动作（小动作 / 嘀咕 / 小剧场）各 1/3，`idle_seconds` 180 秒时平均 9 分钟才轮到一次。
   现在**超过 12 分钟没演小剧场就直接优先演**（`SkitPlayed` 记时间）。
4. 她收起（standby）时根本不待机，那段时间不会演，正常。
日志：`小剧场：名字` 现在每次开演都记一行，方便以后看有没有在演。
